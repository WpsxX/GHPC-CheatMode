# 1.6.4 代码检查与优化说明

本次检查覆盖 ESP、绘制工具、单位登记、无限弹药、无需装填和无敌伤害过滤。构建验证不等于游戏运行验证，目前不能给出 FPS 提升比例或保证所有步兵动画异常均已解决。

验证结果：Release 编译通过；ESP 投影通过 5,013 项数值断言，覆盖 1,000 组镜头位置/偏航/俯仰、缩放、分辨率和单位尺寸组合，以及近裁剪面、屏幕外、无效输入和正交投影。测试使用当前安装的 Unity 托管程序集，不运行游戏。1.6.4 对 `Assembly-CSharp.dll` 做的元数据检查确认了 66 个命名补丁目标/反射成员均存在；本次没有修改 Harmony 补丁目标。这些检查不证明 Harmony 已在游戏中成功应用补丁。

## 本次 ESP 样式恢复与优化

- 对照本地 1.6.3 源码，恢复以单位根节点居中的宽框，框宽至少等于框高（窄步兵恢复为方框），保留阵营颜色和 2 像素边线，标签放在左上方。统一分辨率缩放和近裁剪面保护仍保留。
- 单位列表登记不再同时搜索所有碰撞体；每次 Repaint 最多搜索 4 个单位，避免首次开启或大量增援出现时集中搜索。首次发现时只使用保守边界判断可见性，不绘制临时猜测框；拥挤场景的初始框会在数帧内逐步出现。
- 可见单位边界约 20 Hz 更新，屏幕外降低为 2 Hz；进入保守可见范围时提前更新。每个单位独立安排刷新时间，单位平移和摄像机投影仍随每次 Repaint 更新。
- 每次绘制只读取一次摄像机矩阵和屏幕尺寸，使用托管矩阵运算投影，正常目标跳过近裁剪面边线求交。屏幕外单位跳过标签处理，屏幕内标签 10 Hz 检查名称和距离，文字尺寸随文本或样式对象变化重新计算。
- 未增加设置项，步兵异常碰撞体过滤及固定尺寸后备边界继续保留。

数值测试运行方式（项目目录下）：

```powershell
dotnet msbuild tests\EspGeometry.Tests.csproj /p:Configuration=Release /v:minimal
& .\tests\bin\Release\EspGeometry.Tests.exe
```

## 已处理的问题

- ESP 仅在 Repaint 事件绘制；碰撞体列表复用并错开定期更新，销毁单位同步移除缓存。可见边界约每 0.05 秒更新，投影与单位根节点平移每次重绘更新，避免视角转动造成框滞后。
- 视锥剔除后才投影八个角点；处理近裁剪面穿越和屏幕边缘，宽高使用同一坐标体系。步兵异常碰撞体不会让框无限扩大，全无效时使用固定大小的后备框。
- 方框边线直接绘制矩形，不再做四次旋转/缩放；复用 GUIContent，名称与整米距离不变时复用标签文本。GUIStyle 延迟到 OnGUI 创建，绘制结束恢复 GUI 状态。
- 架设武器在 Awake 登记，GameReady 补扫一次；定期只检查登记列表，不再全局搜索。
- 无限弹药标记只记录初始化；射击和取弹时还会检查当前开关及归属，防止旧玩家单位或阵营变化后继续享受失效的设置。关闭功能不会收回此前已经补入的弹药。
- 装填补弹保存原弹药架、锁定弹药类型和数量；前后使用相同对象计数，避免装填失败时与旧 LoadedClipType 混淆。
- 无敌关闭时提前退出伤害过滤，身体部位枚举仅创建一次。受保护步兵的命中在 gore 激活前阻止，避免只阻止死亡回调而保留断肢激活状态。

## 固定行为

ESP 固定为无限距离，并关闭屏幕中心到单位的连线，仅显示方框及名称、距离标签。这两项不提供配置；此前配置中的 `ESPMaxDistance` 和 `ESPSnapLines` 不再读取。ESP 总开关仍使用原有配置及 F8。

## 尚需实测的优化方向

- 载具无需装填仍按每次射击重建弹链队列。改为增量补弹可以减少高射速武器开销，但必须同时保持曳光弹序列、主/副供弹、膛内旧弹及换弹行为，需要专项测试。
- 无敌弹丸拦截仍有反射字段写入和方法调用。换成字段引用或委托前，需要对照命中音效、引信、HEAT 射流和 AAR 记录验证，避免只改善分配却改变弹道行为。
- 世界边界更新仍会遍历缓存碰撞体。当前已降低屏幕外刷新频率；如需进一步调整可见单位刷新频率或采用校准尺寸，应先用 Unity Profiler 确认实际耗时并检查姿态变化时的框稳定性。

## 游戏内回归建议

在同一大规模任务与相同视角比较 F8 关闭/开启时的帧时间；快速转动镜头，靠近单位，改变分辨率，检查框是否稳定。分别开启/关闭友军无敌攻击步兵，并检查站立、卧倒、死亡和断肢动画；切换控制单位及弹药开关，测试普通装填、换弹种、双供弹和架设武器。最后重载任务检查旧单位框是否残留。
